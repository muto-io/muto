# Environment Variables Reference

Every environment variable Muto actually reads today, grouped by who reads it: `muto-operator`/`muto-mcp` config, the CF platform adapter, standard OpenTelemetry variables, and the variables Muto itself injects into every agent container it spawns.

This list is generated by hand from the source (`os.Getenv`/`env.OrDefault` call sites), not aspirational - if a variable isn't read anywhere in the code, it's not listed here.

## Core Settings

Read by both `cmd/muto-operator` and `cmd/muto-mcp`.

### MUTO_PLATFORM

**Type:** `string`
**Default:** `k8s`
**Valid Values:** `k8s`, `cf`

Selects the underlying platform for agent execution.

```bash
export MUTO_PLATFORM=k8s
```

### MUTO_NAMESPACE

**Type:** `string`
**Default:** `default`

Kubernetes namespace the operator/MCP server watches and creates agent pods in.

```bash
export MUTO_NAMESPACE=muto-system
```

### MUTO_LOG_LEVEL

**Type:** `string`
**Default:** `info`
**Valid Values:** `debug`, `info`, `warn`, `error`

```bash
export MUTO_LOG_LEVEL=debug
```

### MUTO_LOG_FORMAT

**Type:** `string`
**Default:** `json`
**Valid Values:** `json`, `console`

```bash
export MUTO_LOG_FORMAT=console
```

## Operator-Only Settings

### MUTO_METRICS_BIND_ADDRESS

**Type:** `string`
**Default:** `:8080`

Bind address for the Prometheus `/metrics` endpoint. Set to `"0"` to disable the metrics server entirely.

```bash
export MUTO_METRICS_BIND_ADDRESS=:9090
```

### MUTO_HEALTH_PROBE_BIND_ADDRESS

**Type:** `string`
**Default:** `:8081`

Bind address for the `/healthz` and `/readyz` probes.

```bash
export MUTO_HEALTH_PROBE_BIND_ADDRESS=:9091
```

### MUTO_A2A_GATEWAY_IMAGE

**Type:** `string`
**Default:** (required for A2A tenants)

Container image for the A2A gateway deployment. The `TenantReconciler` fails a tenant with `messageBus.type: a2a` if this isn't set - there's no fallback image.

```bash
export MUTO_A2A_GATEWAY_IMAGE=ghcr.io/muto-io/a2a-gateway:latest
```

## CloudFoundry Platform

Read by `cmd/muto-operator` only when `MUTO_PLATFORM=cf`, and passed straight into the CF adapter - none of these use a `MUTO_` prefix.

### CF_API_URL / CF_USERNAME / CF_PASSWORD

**Type:** `string`
**Default:** (required when `MUTO_PLATFORM=cf`)

Cloud Foundry API endpoint and username/password credentials for `NewRealCFClient`.

```bash
export CF_API_URL=https://api.cf.example.com
export CF_USERNAME=muto-service
export CF_PASSWORD=secure-password
```

### CF_ISOLATION_TIER

**Type:** `string`
**Default:** (empty)
**Valid Values:** `shared`, `dedicated`

Tenant isolation strategy for the CF adapter. `dedicated` creates a per-tenant CF org/space; `shared` places tenants in one shared org (see `CF_SHARED_ORG`).

```bash
export CF_ISOLATION_TIER=dedicated
```

### CF_SHARED_ORG

**Type:** `string`
**Default:** (empty)

Name of the shared CF org to use. Required when `CF_ISOLATION_TIER=shared`.

```bash
export CF_SHARED_ORG=muto-shared
```

## OpenTelemetry

Standard `OTEL_*` variables, read directly by the OpenTelemetry SDK/exporters (not through `core/env`) - no `MUTO_OTEL_*` aliases exist. Tracing and OTLP metrics export are both no-ops unless the relevant endpoint variable is set; see [Monitoring and Observability](../operations/monitoring-observability.md) for what gets exported.

| Variable | Effect |
|---|---|
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Sets a single endpoint for both traces and metrics. Setting this alone turns on both `core/tracing` and `core/metrics`. |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | Overrides the endpoint for traces only. |
| `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` | Overrides the endpoint for OTLP metrics only (lets you enable metrics export without tracing). |
| `OTEL_EXPORTER_OTLP_HEADERS` | Extra headers (e.g. auth) sent with every OTLP export request. |
| `OTEL_SERVICE_NAME` | Overrides the default service name (`muto-operator` / `muto-mcp`) reported on every span/metric. |
| `OTEL_RESOURCE_ATTRIBUTES` | Comma-separated `key=value` pairs added as resource attributes. A malformed entry is logged and otherwise ignored, not fatal. |

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
export OTEL_RESOURCE_ATTRIBUTES=deployment.environment=production
```

## Injected Into Agent Containers

Muto doesn't read these - it *sets* them on every agent pod (K8s) or task (CF) it spawns, so your agent code can rely on them being present.

| Variable | Value |
|---|---|
| `MUTO_TENANT` | The tenant that owns this job. |
| `MUTO_ROLE` | This agent's role within the job (e.g. `coordinator`, `worker`). |
| `MUTO_JOB_ID` | The AgentJob's name/ID. |
| `MUTO_MESSAGEBUS_TOPIC` | The message bus topic this agent should use. |
| `MUTO_A2A_GATEWAY` | A2A gateway URL. Only set when the tenant's message bus type is `a2a`. |
| `MUTO_A2A_TOKEN` | A2A auth token, injected via a Secret reference. Only set when the tenant's message bus type is `a2a`. |

## Configuration Examples

### Kubernetes, minimal

```bash
export MUTO_PLATFORM=k8s
export MUTO_NAMESPACE=muto-system
export MUTO_LOG_LEVEL=info
```

### Kubernetes, with tracing and metrics export

```bash
export MUTO_PLATFORM=k8s
export MUTO_NAMESPACE=muto-system
export OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector.observability:4318
```

### CloudFoundry

```bash
export MUTO_PLATFORM=cf
export CF_API_URL=https://api.cf.example.com
export CF_USERNAME=muto-service
export CF_PASSWORD=secure-password
export CF_ISOLATION_TIER=dedicated
```
